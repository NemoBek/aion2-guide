# Aion 2 — интерактивный гайд

Русскоязычный неофициальный гайд по прокачке и первым дням в Aion 2. Основа — [публичная таблица сообщества](https://docs.google.com/spreadsheets/d/e/2PACX-1vQ0C3iKFteGvIbgqNDnQq7bmwIaU23DvjbPa0HPSVAdOOiCeBkEq69Cn8jVMJhToJcztCRylYeTYfOk/pubhtml). Сайт не меняет исходную таблицу.

## Что работает

- Маршрут 1–45 и цели после 45 уровня с чек-листом.
- Сохранение прогресса только в `localStorage` браузера.
- Вкладки фарма, механик и трёх классов; все изображения сайта локальные.
- Статический экспорт для бесплатного GitHub Pages без сервера, базы данных и авторизации.

## Локальный запуск

Нужны Node.js 22.13+ и pnpm 11. В этой папке выполните:

```bash
pnpm install --frozen-lockfile
pnpm dev
```

`pnpm build` проверяет снимок и собирает обычную статическую версию в `out/`. `pnpm build:pages` делает то же самое с базовым путём `/aion2-guide/` для GitHub Pages.

## Публикация на GitHub Pages

1. Создайте **публичный** репозиторий с именем `aion2-guide` и основной веткой `main`.
2. Загрузите содержимое **этой папки** в корень репозитория через Git или GitHub Desktop. Папки `node_modules`, `.next`, `out`, `.sites-runtime` исключены через `.gitignore`; файл workflow в скрытой папке `.github` должен попасть в репозиторий.
3. В GitHub откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
4. Запустите **Actions → Publish Aion 2 guide → Run workflow** или дождитесь сборки после загрузки в `main`.

После успешного запуска адрес будет `https://<ваш-логин>.github.io/aion2-guide/`. Если репозиторий будет называться иначе, измените `/aion2-guide` в `scripts/build-pages.mjs`.

Пример первой отправки через Git из этой папки (подставьте свой логин):

```bash
git init -b main
git add .
git commit -m "Initial Aion 2 guide"
git remote add origin https://github.com/<ваш-логин>/aion2-guide.git
git push -u origin main
```

## Обновление данных

`pnpm sync` читает только публичные вкладки исходной таблицы. Автоматически обновляются проверенные позиции раннего фарма, две ссылки на билд каждого из трёх классов, а также изображения маршрута и пяти механик. Если формулировка фарма изменится, синхронизация остановится для редакторской проверки: так исходные опечатки и посторонний текст не попадут на сайт. Остальные тексты остаются отредактированным кратким гайдом: визуальная таблица не даёт надёжно сопоставить каждую её ячейку с карточкой сайта. Изображения классов оставлены в проверенных локальных галереях, поскольку в исходных вкладках есть и исключённые макросы.

Скрипт требует ожидаемую структуру вкладок, проверяет поля и ссылки, скачивает изображения только с `docs.google.com`, проверяет MIME, сигнатуру и размер до 5 МБ. Повреждённый или неполный ответ завершает синхронизацию с ошибкой и оставляет прежний JSON-снимок. Если содержимое не изменилось, снимок и дата не перезаписываются. Дата в футере показывает последнее успешное **изменение данных**.

Workflow `.github/workflows/pages.yml` запускается при загрузке в `main`, вручную и два раза в сутки. По расписанию он сначала синхронизирует данные, затем проверяет и собирает сайт, сохраняет обновлённый снимок в репозитории и только после этого публикует сборку. При любой ошибке публикация не выполняется, действующий сайт остаётся доступным.

Снимок: `data/guide.snapshot.json`. Его структура проверяется `scripts/validate-snapshot.mjs`. Прогресс посетителей не попадает ни в таблицу, ни в GitHub.
